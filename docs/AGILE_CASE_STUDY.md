# Agile Delivery Case Study

## Delivery context

The course work used a small product increment to practice backlog thinking, role clarity, test planning, review, and retrospective improvement.

## Evidence map

| Practice | Evidence represented | Employer signal |
| --- | --- | --- |
| Product ownership | User stories and prioritization | Turns needs into actionable backlog items |
| Quality ownership | Test-case design | Connects acceptance criteria to verification |
| Scrum facilitation | Team charter and role journals | Communicates responsibilities and removes ambiguity |
| Inspect and adapt | Sprint review and retrospective | Uses feedback to improve the next increment |
| Delivery | Java Swing slideshow | Carries a small feature through implementation |

## Professional limitations

This is a course-scale example rather than a production product. The public candidate intentionally excludes raw Office files and unverified image assets. A production workflow would add issue tracking, automated UI tests, accessibility checks, and a repeatable build pipeline.
